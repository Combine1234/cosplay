# CLOSET — Cosplay Marketplace MVP

ต้นแบบเว็บ marketplace สำหรับซื้อและส่งต่อชุดคอสเพลย์ พร้อม Virtual Cosplay Mannequin แบบ 2D ผู้ใช้สร้างหุ่นจากส่วนสูง อก เอว สะโพก และไหล่ แล้วลองชุดหลายเลเยอร์ เปลี่ยนไซซ์ ดูผลประเมินความพอดี และซื้อแบบจำลองได้ในเว็บเดียว

ข้อมูล Cosplay เก็บใน IndexedDB ด้วยคีย์ `cosplay-v1` แยกจากข้อมูล Closet รุ่นก่อน จึงไม่ลบหรือแปลงประวัติเดิม รูปและรายการสาธิตทั้งหมดเป็นภาพ SVG ออริจินัลที่สร้างใน repository นี้

## เปิดเดโม

ต้องใช้ Node.js 20 ขึ้นไป และเปิดผ่าน local server เพราะหน้าเว็บใช้ ES modules:

```bash
npm start
```

จากนั้นเปิด [http://127.0.0.1:4173](http://127.0.0.1:4173)

## เส้นทางเดโมแนะนำ

1. หน้า **Marketplace** ค้นหาตัวละครหรือชื่อชุด และกรองไซซ์ ราคา และสภาพ
2. เปิด Luna Astralis เลือกไซซ์ แล้วกด **Try On**
3. เปิด **แก้ไขสัดส่วนเพื่อเปรียบเทียบ** หรือสร้าง **My Mannequin** จาก preset Slim, Regular หรือ Curvy แล้วปรับค่าจริง
4. เปลี่ยนไซซ์หรือชุดในห้องลอง สังเกตภาพเลเยอร์ชุดและ Fit Summary ที่เปลี่ยนตามข้อมูลวัด
5. กด **Buy Now** และยืนยันซื้อจำลอง รายการจะปรากฏใน **My Closet → Purchases** ทันที
6. สลับไปบัญชีเจ้าของประกาศ แล้วดู **Sold** และ **Earnings**
7. กด **ลงขายชุด** เพื่อทดลองฟอร์ม 4 ขั้น: ข้อมูลชุด, ไซซ์และขนาด, รูปและพรีวิว, ราคาและเผยแพร่
8. เปิด Flora Sylven หรือ Mika Hanami เพื่อดูภาพ **Flaw / Defect** และเครื่องมือซูม/เลื่อนภาพต้นฉบับ

## พฤติกรรมสำคัญ

- หนึ่งประกาศมีหลายไซซ์ แต่ละไซซ์มีราคา ขนาดวัด และสต็อกหนึ่งชิ้นแยกกัน
- การซื้ออ่านสถานะล่าสุด ตัดสต็อก และสร้างสำเนาหลักฐานคำสั่งซื้อใน IndexedDB transaction เดียว
- Fit Summary ใช้กฎจากขนาดวัด แสดง Tight, Good, Slightly Loose, Loose, Short, Long หรือยังประเมินไม่ได้
- หุ่นเปลี่ยนไหล่ อก เอว สะโพก และสัดส่วนแนวตั้งแยกกัน ส่วนขนาดภาพชุดมาจากตัวแปรของชุด ไม่ยืดตามร่างกายผู้ใช้
- ชุดที่ไม่มี PNG โปร่งใสยังลงขายและซื้อได้ โดยแสดงภาพต้นฉบับคู่หุ่นแทน
- ผู้ขายต้องระบุรูปตำหนิและคำอธิบายเมื่อเลือกสภาพ “มีตำหนิ”

## ทดสอบ

```bash
npm test
node --check app.js
node --check cosplay-domain.js
node --check cosplay-seller.js
node --check mannequin.js
```

ชุดทดสอบอัตโนมัติครอบคลุมขอบเขต fit ทุกสถานะ การตรวจสัดส่วน สิทธิ์บัญชี สต็อกแยกไซซ์ การซื้อซ้ำ ความเป็นอะตอมของการซื้อ การเก็บ snapshot การลงขาย และการคงข้อมูลแต่ละบัญชี

## ข้อจำกัดของ MVP

- ไม่มี backend, การชำระเงินจริง, ขนส่ง, ยืนยันตัวตน หรือแจ้งเตือนภายนอก
- ข้อมูลอยู่ในเบราว์เซอร์และเครื่องเดียว อาจหายเมื่อล้างข้อมูลเว็บไซต์
- Virtual preview เป็นภาพซ้อน SVG 2D และผล fit เป็นค่าประเมินจากกฎ ไม่ใช่ cloth simulation หรือการรับประกันความพอดี
- ผู้ขายต้องเตรียม PNG โปร่งใสเอง ระบบไม่ตัดพื้นหลังและไม่วิเคราะห์รูปด้วย AI
- ผู้ช่วยคำบรรยายและราคาใช้กฎกับข้อมูลในระบบ และเปิดเผยจำนวนรายการเทียบเคียง
